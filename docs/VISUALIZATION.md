# Search explorer v1

The explorer is a **rendered snapshot** of one experiment, not a polling dashboard. It is regenerated by the
harness as events finish. Refresh the browser to load a newer snapshot. No server, CDN, fonts, or npm runtime
dependencies are required to open the default HTML.

```bash
./rsi render experiments/my-run
xdg-open experiments/my-run/tree.html
```

## Read an experiment

- **Tree:** drag the canvas to pan, scroll to zoom, use +/- for centered zoom, Fit to see the whole tree, and Best
  to select/focus the best official result. Tab to a node and use Enter/Space to select it.
- **Paths:** gold marks the best-score ancestry; the selected ancestry is dashed. Node status/audit colors are
  separate from numerical rank. “Best” is not a claim that a gain is statistically significant.
- **Inspector:** Overview presents hypothesis, observed result, recorded git log/diffstat, parent comparison,
  audit claim check, and proposed next experiments. Handoff, progress, raw metrics, and failure diagnosis have
  separate tabs. Changes shown are the recorded commit log/diffstat, not a live code diff viewer.
- **Curve:** select completed-experiment count or elapsed wall-clock time. The incumbent starts at the valid
  baseline. Only `done` nodes with finite official scores may improve it. Failed/invalid outcomes appear as crosses,
  even when stale scores remain in their records. Click a point to inspect the node.
- **Ordering:** new runs use persisted completion order to break same-second ties. Legacy runs fall back to
  recorded timestamps and node ID; their exact same-second order cannot be recovered. Time-axis plots are
  chronological and include idle/restart gaps; missing timestamps disable that axis rather than inventing times.
- **References:** optional reference lines are off by default so distant reference values do not flatten the curve.
  These are task-defined comparisons, not a claim that their evaluation protocol matches the current run.
- **Ledger:** filter by status or search ID/title/hypothesis, then select a node. The ledger, curve, and tree share
  selection. Final-level evaluation is shown separately from the official search score.
- **Theme:** follows the OS by default; the theme button stores an optional local preference. The layout also
  works on narrow screens. Tree zoom buttons remain available on touch devices.

## Sharing

`tree.html` embeds experiment documents and metrics. It is easy to share, **not automatically anonymized**:
review logs, data examples, paths, human notes, and model output for private information before publishing.
Document contents are displayed as text, not executed HTML.

The existing `render_bundle()` API emits `index.html`, `data.js`, and `tree.js` for static hosts that forbid inline
scripts. It has the same UI. Inline CSS is still used, as in the original renderer.

## Tests

```bash
python3 -m unittest discover -s tests -p 'test_render.py' -v
node --test tests/test_tree_model.cjs
```

The optional browser test requires Playwright and a Chromium browser, installed separately from this project:

```bash
# Example isolated tooling installation; not required to run pi-rsi.
npm install --prefix /tmp/rsi-browser-tools playwright
PLAYWRIGHT_MODULE=/tmp/rsi-browser-tools/node_modules/playwright \
  CHROME_BIN=/usr/bin/google-chrome node tests/test_tree_browser.cjs
```

The browser test uses a disposable fixture/profile (browser sandbox disabled in the test launcher), checks offline
and external-script rendering, selection, pan/zoom, tabs, filters, theme, chart interaction, keyboard selection,
empty/baseline-only runs, escaped documents, and mobile overflow. Screenshots are saved under a reported temporary
directory. Do not use that test launcher to browse untrusted sites.

## Deliberately outside v1

Event-by-event replay, arbitrary two-node code comparison, GPU-hour axes, live streaming, and public-export
redaction are not implemented. This version focuses on making the existing search and its evidence readable.
